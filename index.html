01 / PROJECT OVERVIEW

결제 성공 이후까지 생각한 구현

정상 경로와 실패 경로를 함께 다루며,
거래 상태를 설명할 수 있는 시스템을 목표로 했습니다.

01 — BACKGROUND

결제 연동을 하나의 시스템으로

브라우저 인증과 서버 승인이 분리되는 PC 표준결제 구조를 이해하고, 주문 생성부터 거래조회까지 이어지는 흐름을 구현했습니다.

02 — SCOPE

주문 · 승인 · 조회 · 취소

FastAPI와 SQLite를 중심으로 승인정보를 보존하고, PAYCO 응답 처리, 전체취소, 감사 이력과 데이터 보존 마이그레이션까지 범위를 확장했습니다.

03 — CHALLENGE

응답이 없을 때의 올바른 판단

타임아웃을 곧바로 실패로 단정하지 않고, 중복 요청과 저장 실패를 고려해 거래조회로 상태를 확인하는 복구 흐름을 설계했습니다.

  4. KCP 결제승인 API 연동

  9. PAYCO 카드·포인트 응답 처리
  10. PAYCO 단독 호출 모드

03 / PAYMENT FLOW

하나의 거래, 여섯 단계의 확인

단계를 선택하면 각 경계의 역할을 확인할 수 있습니다.

STEP 01 / ORDER

금액의 기준은 서버가 보관합니다.

주문을 생성하고 서버에서 결제 금액을 관리합니다. 이후 인증·승인 과정에서 전달된 값을 주문 정보와 대조할 기준을 마련합니다.

CHECKPOINT클라이언트 입력을 금액의 근거로 신뢰하지 않기동작 설명용 인터랙션 · API 요청 없음

04 / RELIABILITY & SECURITY

정상 응답보다 중요한, 예외의 설계

불확실한 상태를 드러내고,
검증 가능한 근거로 다음 동작을 결정합니다.

⌁

신뢰 경계에서 검증

서버 주문 금액과 인증 결과를 대조하고, Origin 및 CSRF 검증으로 요청의 출처와 유효성을 확인합니다.

금액 검증Origin / CSRF
⇉

중복 실행 제어

중복 승인과 동시 요청을 방지합니다. 취소 처리권을 관리해 동일 거래의 취소 작업이 겹치는 상황을 다룹니다.

동시성취소 처리권
↺

조회로 확인하는 복구

타임아웃과 저장 실패를 고려하고, 결과가 불명확한 거래는 UNKNOWN으로 관리합니다. 거래조회로 상태를 확인해 복구합니다.

UNKNOWN조회 기반 복구
≡

판단의 근거 보존

승인정보와 취소 감사 이력을 저장합니다. 데이터 보존 마이그레이션으로 구조 변경 이후에도 거래 기록을 유지합니다.

감사 이력데이터 보존
응답 타임아웃→UNKNOWN→서명 기반 거래조회→외부 상태 대조 및 복구

05 / PAYCO INTEGRATION

같은 결제 흐름,
다양한 결제 수단.

KCP 표준결제 기반 PAYCO 연동과 단독 호출 모드를 구현했습니다. 카드·포인트·혼합결제의 응답 차이를 구분해 처리합니다.

실제 활성화 환경 테스트 대기
카드 결제카드 응답 처리모의 검증
포인트 결제포인트 응답 처리모의 검증
혼합결제카드 + 포인트 응답 처리모의 검증

실제 PAYCO 결제 승인 성공은 검증하지 않았습니다.

07 / DEVELOPMENT PROCESS

명세를 읽고, 구현하고, 검증하다.

Windows PowerShell · VS Code
OpenAI Codex · NHN KCP MCP

  1. 01

    공식 명세 조사

    NHN KCP MCP로 PC 표준결제 흐름과 요청·응답 명세를 조사하고 구현 범위를 정리했습니다.

  2. 02

    요구사항 정의와 구현

    VS Code와 Codex를 활용해 주문, 인증, 승인, 조회, 취소의 책임을 구분하고 코드를 구현했습니다.

  3. 03

    실제 환경과 모의 환경 검증

    실제 KCP 테스트 환경에서 카드 승인·조회를 확인하고, 모의 테스트로 오류·동시성·복구 경로를 점검했습니다.

  4. 04

    불확실한 상태의 처리 개선

    취소 타임아웃은 UNKNOWN 상태와 조회 기반 복구로, 중복 요청은 실행 제어로 다루고 감사 이력을 남기도록 구성했습니다.

AI 보조와 개발자 검증의 역할

Codex는 코드 작성과 문제 해결을 보조했습니다. 요구사항 판단, 구현 내용 검토, 실제 환경 확인과 검증 범위의 구분은 개발자의 역할입니다. AI 생성 코드 자체를 검증의 근거로 삼지 않습니다.
